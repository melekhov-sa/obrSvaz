# Admin tools enhancements — design

## Контекст

Бот из [2026-07-22-vpn-feedback-bot-design.md](2026-07-22-vpn-feedback-bot-design.md) уже развёрнут и работает. После первого прогона в проде выявились три небольших пробела в админском UX:

1. `/stats` показывает только статистику по жалобам — нет числа зарегистрированных/привязанных пользователей бота.
2. Список команд в Telegram (выпадающее меню при вводе «/») пустой — бот никогда не вызывал `set_my_commands`, хотя сами команды работают при ручном вводе.
3. Нет способа снять привязку `marzban_login` у пользователя — обнаружилось, когда админ сам случайно перешёл по чужой `/genlink`-ссылке и привязал свой аккаунт не под тем логином.

Это точечные дополнения к уже принятой архитектуре (aiogram 3, SQLite, aiosqlite), без новых модулей — правки в уже существующих `bot/db/users_repo.py`, `bot/handlers/admin.py`, `bot/main.py`.

## 1. Расширение `/stats`

В начало вывода `/stats` (`bot/handlers/admin.py`) добавляются две строки перед существующей статистикой по жалобам:

```
Зарегистрировано в боте: <N>
Привязано к панели: <M>
```

`N` — длина списка из `users_repo.get_all_users(conn)`, `M` — длина списка из `users_repo.get_linked_users(conn)`. Обе функции уже существуют и протестированы (Task 3 исходного плана) — новых запросов к БД не требуется, только `len()` от уже вызываемых списков.

## 2. Меню команд Telegram

В `bot/main.py`, сразу после создания `Bot` и до `dp.start_polling(...)`, добавляется регистрация команд через `bot.set_my_commands()` с двумя областями видимости (scope):

- **Публичная** (`BotCommandScopeDefault()`) — видна всем пользователям:
  - `/complain` — сообщить о проблеме с VPN
  - `/status` — статус вашего аккаунта
  - `/faq` — инструкции по подключению
- **Админская** (`BotCommandScopeChat(chat_id=config.admin_id)`) — видна только в чате администратора, включает публичный набор плюс:
  - `/genlink` — сгенерировать ссылку для привязки пользователя
  - `/unlink` — снять привязку пользователя от логина
  - `/broadcast` — разослать сообщение всем пользователям
  - `/stats` — статистика

Регистрация выполняется один раз при старте процесса (не при каждом сообщении). Telegram применяет разные списки автоподстановки в зависимости от того, кто открывает меню «/» — админский чат видит полный набор, остальные — только публичный.

## 3. `/unlink <логин>` — снять привязку

Новая admin-only команда в `bot/handlers/admin.py` (внутри `create_admin_router`, как остальные админ-команды).

**Поведение:**
- `/unlink <логин>` ищет пользователя, у которого сейчас `marzban_login == <логин>`.
- Если найден — обнуляет его `marzban_login` и `linked_at` (`NULL`), отвечает: `Отвязано: <логин> (был привязан к id <telegram_id>)`.
- Если не найден — отвечает: `Активной привязки для логина <логин> не найдено.`
- Без аргумента — подсказка по использованию (`Использование: /unlink <логин_в_панели>`), как у `/genlink`.

**Новая функция в `bot/db/users_repo.py`:**

```python
async def unlink_by_login(conn: aiosqlite.Connection, marzban_login: str) -> aiosqlite.Row | None:
    cursor = await conn.execute("SELECT * FROM users WHERE marzban_login = ?", (marzban_login,))
    row = await cursor.fetchone()
    if row is None:
        return None
    await conn.execute(
        "UPDATE users SET marzban_login = NULL, linked_at = NULL WHERE marzban_login = ?",
        (marzban_login,),
    )
    await conn.commit()
    return row
```

Возвращает снятую строку (для сообщения с `telegram_id`) или `None`, если под этим логином никто не привязан. После `/unlink` логин свободен — по нему можно снова сгенерировать `/genlink` для нужного пользователя без конфликтов (в отличие от повторной генерации `/genlink` для уже занятого логина, которая и так переназначает привязку — `/unlink` даёт явный способ снять её без немедленной повторной выдачи).

## Тестирование

- `unlink_by_login` — юнит-тест в `tests/test_users_repo.py`, по образцу существующих тестов этого файла: найден/не найден, реально обнуляет поля, не трогает других пользователей.
- Расширенный `/stats` и `/unlink`-хендлер, регистрация меню команд — без новых автотестов, по уже принятому в исходной спеке решению (хендлеры проверяются вручную). Ручная проверка: `/unlink` на реально привязанном логине и на несуществующем; `/stats` показывает верные числа; меню «/» отличается у админа и у обычного пользователя.

## Вне рамок

- Отвязка по `telegram_id` (только по логину — этого достаточно, все команды админа и так оперируют логинами).
- Массовая отвязка/список всех текущих привязок отдельной командой (не запрошено).
