# Кнопки, эмодзи и графики — design

## Контекст

Бот уже развёрнут и активно используется. Этот заход — визуальный/UX-апгрейд поверх существующей функциональности (не меняет бизнес-логику): главное меню на inline-кнопках, эмодзи по всем сообщениям, текстовый график жалоб для админа, шкала использования трафика в `/status`. Все данные для графиков уже есть в системе — новых запросов к Marzban не требуется.

## 1. Главное меню на кнопках

`/start` (как раньше — с опциональной привязкой по токену) и новая команда `/menu` показывают inline-клавиатуру:

```
🔴 Сообщить о проблеме
📊 Мой статус
📖 FAQ
```

Если сообщение отправлено админом (`message.from_user.id == admin_id`), добавляется четвёртая кнопка:

```
📈 Статистика
```

**Механика:** каждая кнопка — `InlineKeyboardButton` с `callback_data` (`menu:complain`, `menu:status`, `menu:faq`, `menu:stats`). Логика каждой команды выносится в отдельную переиспользуемую async-функцию, которая принимает то, что уже есть у обоих вызовов (`conn`, `marzban`/не нужен для faq, `from_user_id` и объект для ответа), и вызывается:
- из существующего `Command(...)`-хендлера — как раньше;
- из нового `CallbackQuery`-хендлера в `bot/handlers/menu.py` — по `callback_data`.

Для `menu:complain` кнопка не может сама принять текст жалобы (в отличие от команды `/complain` это всё ещё двухшаговый процесс) — нажатие переводит в то же FSM-состояние `ComplainStates.waiting_for_text`, что и команда, и просит описать проблему.

Текстовые команды (`/complain`, `/status`, `/faq`, `/stats`, `/genlink`, `/broadcast`, `/unlink`) продолжают работать как раньше — кнопки это альтернативный вход, не замена.

## 2. Эмодзи

Единая раскладка по всему боту:

| Эмодзи | Значение |
|---|---|
| 🔴 | новая жалоба (и админу, и в подтверждении пользователю) |
| ✅ | успех/подтверждение (жалоба зарегистрирована, привязка выполнена) |
| ⚠️ | предупреждение/ошибка/недействительная ссылка |
| 🌐 | статус VPN-аккаунта |
| 📊 / 📈 | статистика |
| 🔗 | привязка (`/genlink`) |
| 🔓 | отвязка (`/unlink`) |
| 📢 | рассылка (`/broadcast`) |
| 📖 | FAQ |

Кнопки выбора платформы в FAQ получают иконки: 📱 iOS, 🤖 Android, 🪟 Windows, 🍎 macOS, 📶 Роутер.

Это точечная правка текстов ответов во всех существующих хендлерах — не меняет логику, только формулировки.

## 3. Текстовый бар-чарт жалоб в `/stats`

В конец существующего вывода `/stats` (после раздела «По пользователям») добавляется график по дням за последние 14 дней:

```
19.07 ████████░░ 4
20.07 ██░░░░░░░░ 1
21.07 ██████████ 5
```

Формат строки: `ДД.MM` + 10-символьная шкала (`█` — заполненная часть, `░` — пустая, пропорционально максимуму за период) + число жалоб за день. День с 0 жалоб — строка из одних `░` и `0`. Если максимум за период — 0 (жалоб не было вообще), все строки показываются пустыми, без деления на ноль.

**Новая функция в `bot/db/complaints_repo.py`:** `count_by_day(conn, since_iso: str) -> list[aiosqlite.Row]` — `SELECT DATE(created_at) as day, COUNT(*) as cnt FROM complaints WHERE created_at >= ? GROUP BY day ORDER BY day`. Дни без единой жалобы не попадают в результат запроса — рендер-функция сама достраивает полный диапазon из 14 дней, подставляя 0 для отсутствующих дат.

**Чистая функция рендера** (без доступа к БД) в `bot/formatting.py` (новый модуль — форматирование, используемое и в графике жалоб, и в шкале трафика, живёт в одном месте): `render_daily_bar_chart(counts_by_day: dict[str, int], days: int) -> str`, принимает уже посчитанные числа и достраивает недостающие дни сама, возвращает готовый многострочный текст.

## 4. Шкала использования трафика в `/status`

Дополняет существующий вывод `/status` строкой вида:

```
[███████░░░] 68% (34.2 / 50.0 ГБ)
```

Если `data_limit` не задан (безлимит) — шкала не показывается вообще (делить нечего), выводится как сейчас: `Трафик: 34.2 ГБ / безлимит`.

**Чистая функция рендера** в том же `bot/formatting.py`: `render_usage_bar(used_bytes: int, limit_bytes: int | None, width: int = 10) -> str | None` — возвращает `None`, если `limit_bytes` пуст или равен 0 (тогда `/status` просто не добавляет строку шкалы), иначе строку шкалы. Использование, превышающее лимит (100%+), показывается как полностью заполненная шкала с реальным процентом (`[██████████] 120% (60.0 / 50.0 ГБ)`), без обрезания процента — это сигнал, что лимит уже превышен.

## Тестирование

- `render_daily_bar_chart` и `render_usage_bar` — чистые функции, юнит-тесты в `tests/test_formatting.py`: пустой период (все нули), обычное распределение, лимит не задан (`None`), превышение лимита (>100%).
- `count_by_day` — юнит-тест в `tests/test_complaints_repo.py`, по образцу существующих функций этого файла.
- Кнопки/меню/эмодзи в текстах хендлеров — без автотестов, по уже принятому в проекте решению (ручная проверка после деплоя).

## Вне рамок

- Графики на основе истории трафика из Marzban (endpoint истории не подключён, есть не в каждой версии панели — см. обсуждение).
- Изображения/PNG-графики (matplotlib и подобное) — выбран текстовый вариант.
- Постоянная reply-клавиатура (нижняя панель кнопок) — используется только inline-меню по `/start`/`/menu`.
